# Synthesizing the improver

The six proposal slots use the same typed enumerator and current learned
library as task synthesis. Mutations replace seeded incumbent subtrees with
closed, type-compatible terms from that enumerator. Inlining the primitive
counterfactual freshens polymorphic schemes independently and preserves closed
body scope. The initializer is the Stage 1 constant-zero heuristic.

All valid candidates, including duplicates, are screened and logged. Full
confirmation and strict validation adoption follow the registered protocol.
The learner never loads the sealed evaluation partition. Each proposal and
every complete task candidate attempted during screening, incumbent assessment
and confirmation contributes to reported logical compute.

Pure heuristic scores are memoized only within one task search: candidate
output tuple, size and depth identify all changing arguments; target outputs,
library, program and interpreter budget are fixed in that call. Complete task
evaluation is charged before score-cache lookup. Callback count and actual
interpreter evaluations/steps are separate telemetry. This changes runtime cost
without changing scores, the candidate prefix or the frozen input format.

Stage 4 validation: **87 tests passed in 14.988 seconds** plus an independent
scope/type/accounting review. A real seed-11 wake–sleep state was tested on
VALIDATION: all six heuristic proposals were evaluated, 2361 inner task
candidates were attempted, and no candidate strictly improved the incumbent
1/12 solved fraction. Heuristic synthesis used 306.097 CPU seconds and 306.135
wall seconds. The run contains no sealed performance measurements.

The final parameters and numeric forecasts are committed in `PREDICTIONS.md`
before the final study begins.
