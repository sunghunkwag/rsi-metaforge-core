# Bounded autonomous refinement of the evaluation procedure

Register this protocol before executing it. Previous studies, decisions and
source stay unchanged. This study connects failure diagnosis, intervention
proposal, counterfactual verification, preservation and next-cycle execution
inside the runtime. It tests one evaluation-method refinement; it does not
synthesize arbitrary source edits or establish recursive task capability.

The coordinator reads development assessment calls from the first procedure
study. It reconstructs their exact scopes from the saved initial states, task
identities, logged heuristic programs, budgets and search bounds. Result aliases
and cached assessments cannot be credited as repeated actual work. Repeated
scopes, task-group overlap and early bounded termination are separate observed
patterns. Unobserved planning, tools or model causes remain unknown.

The smallest proposed intervention is per-task shared evaluation evidence.
Cross-budget certificates require both observed early termination and passing
budget-counterexample verifiers. Missing history or proof cannot activate a
change. The coordinator describes its failure pattern, diagnosis, hypothesis,
mechanism and scientific limits rather than installing a task heuristic.

Cycle 1 counterfactually executes the current whole-group memory and proposed
memory on identical calls: first four sorted original VALIDATION tasks, then
all twelve VALIDATION tasks, both at candidate budget 64. Both start with empty
caches. For each seed 11, 22 and 33 use that seed's previously saved initial
learner state and its zero incumbent. Grammar, recognizer, library, examples,
heuristic and search bounds match exactly across procedures; the state is
not retrained or modified. No logged rejected heuristic is installed.

Admission requires all three completed seed comparisons, exact scientific
equality, nonincrease in every actual candidate/interpreter/heuristic/verifier
work component and a strict saving in at least one component on every seed.
Require passing, identified external exact-reuse and certificate verifiers.
Publish the decision and supporting rule before opening the next task partition.
Missing comparisons are UNKNOWN; differences or regressions reject the change.
CPU includes key construction and is reported separately. A logical-work gain
does not imply physical throughput gain when cache overhead increases CPU.

Cycle 2 uses the admitted memory factory automatically. Compare the original
procedure and selected procedure on the first three confirmation tasks followed
by all six confirmation tasks, again budget 64, fresh per-seed caches, unchanged
initial states and bounds. These families already served the earlier development
studies; call this transfer of the method, not previously unseen task performance.
The independent reporting audit and original TEST remain closed. Negative
transfer evidence cannot be silently kept as a successful generalization.

Save paired task-specific measurements, actual work, CPU, scope observations,
factory transitions, rule evidence and all eleven requested fields after every
completed seed and decision. Keep successful method abstractions in the runtime's
rule history; the next cycle must use that history rather than a manual backend
choice. No narrative or unit-test-only gain is accepted.

A score-blind parent watchdog covers one spawned worker and parent CPU, with a
300 aggregate CPU-second ceiling. Preserve partial checkpoints if interrupted;
no incomplete verification can activate a rule. Runtime remains Python standard
library plus NumPy with one thread and no network, LLM, model API or new DSL
primitive. Positive evidence here is a bounded loop-level evaluation improvement;
learned meta-policy improvement and cumulative task-solving RSI remain separate
unmet claims unless their own comparisons establish them.
